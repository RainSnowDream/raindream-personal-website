## 写博客

打开 `posts.js`，在数组末尾加一篇（`id` 必须唯一，不能和已有文章重复）：

```js
{
  id: 6,
  date: '2026-08-06',
  tags: ['生活'],
  title: '标题',
  excerpt: '摘要',
  body: `正文，Markdown 格式，支持 [链接](url)`
}
```

### ⚠️ 正文里的反引号必须转义（最容易踩的坑）

`body` 是**模板字符串**（整段被一对反引号包着），所以正文里：

| 你想写 | 必须写成 |
|---|---|
| 反引号 `` ` ``（比如 Markdown 的行内代码） | `` \` `` |
| `${` | `\${` |

**漏了转义 → 整个 `posts.js` 语法出错 → 博客页一篇文章都显示不出来**（会显示「文章数据没能加载」而不是白屏）。

所以每次改完 `posts.js`，**刷新一下博客页确认文章还在**，再推送。

> 字段也可以少写：`date` / `tags` / `title` / `excerpt` / `body` 缺哪个都会用默认值兜底，
> 不会让整页崩掉；但 `id` 必须写且唯一。

## 修改代码

- **共享样式** → 打开 `styles.css`（导航、主题、配色变量、页脚等两页共用的部分）
- **共享交互** → 打开 `common.js`（主题切换、移动端导航、回到顶部、滚动高亮等）
- **主页内容** → 打开 `index.html`，搜索对应中文就能定位到要改的位置
- **联系方式** → 打开 `index.html`，搜索 `contact-grid`，改里面几个 `<a href="...">` 的链接和文字
- **关于我** → 打开 `index.html`，搜索 `关于我` 或 `about-text`，直接改段落文字
- **配色** → 打开 `styles.css`，搜索 `:root`，蓝粉颜色在 CSS 变量 `--blue` 和 `--pink` 里
- **头像** → 替换 `avatar.webp`（页面内头像）；`avatar.jpg` 用作社交分享图（og:image），保持同名即可

- **Markdown 渲染库** → `marked.umd.js` 是直接下载的 `marked@18.1.0` 里的 `lib/marked.umd.js`；
  要升级就下载新版覆盖它即可（脚本走网络优先，老访客刷新就是新版，不用动 `CACHE_VERSION`）

页面专属的样式仍留在各自的 `<style>` 里，交互逻辑留在各自的 `<script>` 里。

### 深浅色切换按钮（第三方组件，已就地收养）

导航栏右边那个白/夜切换按钮不是自己写的，来自
[Day-night-toggle-button](https://github.com/Xiumuzaidiao/Day-night-toggle-button) 的
**「白天黑夜切换按钮 4.0」**（作者 Xiumuzaidiao，**ISC 许可证**，可自由使用/修改/分发，
保留 `theme-button.js` 开头那段声明即可）。

它是个 **Web Component**（自定义元素 `<theme-button>`），内部用 **Shadow DOM 封闭**——
所以它自带的 `* { margin:0; transition:.7s }` 这类演示页样式**不会污染整站**，
`styles.css` 里只需要给它一个尺寸盒子。

**想改大小**：只改 HTML 里那个标签的 `size` 属性（`index.html` / `blog.html` 各一处）：

```html
<theme-button class="theme-toggle" id="themeToggle" size="1.3" ...></theme-button>
```

内部固定 180em × 70em，字号 = `size ÷ 3` px，所以：

| size | 换算 | 实际尺寸 |
|---|---|---|
| `3` | 1px 字号 | 180 × 70（原版演示大小） |
| `1.3` | 0.43px 字号 | **约 78 × 30（当前使用）** |
| `1` | 0.33px 字号 | 约 60 × 23 |

> 改小了云朵和星星的细节也会一起变小（它们都是按 em 算的），别再往小了调。

**接进本站时改了 7 处**（都在 `theme-button.js` 里，代码里带「本站改动」注释）：

1. `.components` 的 `position:fixed` → `absolute`：原版固定在视口上，放进导航栏会随页面滚动飘走；
2. 删掉「跟随系统主题自动切换」：本站规则是首次跟系统、之后以访客自己的选择为准
   （跟随会覆盖访客的手动选择）；
3. **键盘无障碍**：宿主元素 `role="switch"` + `tabindex="0"`，Enter / 空格可切换
   （原版内部是 `div` + `onclick`，键盘和读屏都用不了）；
4. 初始主题改读本站的 `<html data-theme>`（配合页头那段防闪白的内联脚本，避免先画成白天再跳一下）；
5. 切换时同步 `aria-checked`；宿主被重复挂载时不再重建 Shadow DOM；
6. 尊重系统的「减少动态效果」（`prefers-reduced-motion`）；
7. 对外只抛一个 `change` 事件（`e.detail` = `'light'` / `'dark'`），过场动画在 `common.js` 里单独做
   （见下一节）。

### 导航栏的入场动画（想调节奏就改三个变量）

进页面时导航栏会**整体落下**，里面的 logo / 菜单 / 音乐 / 主题按钮依次**淡入上浮**。
节奏统一在 `styles.css` 顶部这三个变量里，**改它们就行，不用碰动画代码**：

```css
--nav-in-dur:.45s;                          /* 每一项淡入用多久 */
--nav-in-step:.05s;                         /* 相邻两项之间错开多久（越大会越「一个个来」） */
--nav-in-ease:cubic-bezier(.22,1,.36,1);    /* 缓动：现代 UI 常用的「快出缓停」 */
```

顺序由 `animation-delay:calc(var(--nav-in-step) * N)` 决定：logo = 1、菜单 1~4 = 2~5、主题按钮 = 6。

几个已经处理掉的坑：

- **只用 `opacity` + `transform`** 做动画（走合成层、不触发布局），不会掉帧；
- **不带 `transition:all`**：导航栏收缩那条过渡只写 `height / background-color / box-shadow / border-color`，
  免得滚动时连 `backdrop-filter`（毛玻璃）都跟着重算；
- **不透明度提前到位**（关键帧 55% 就到 1）：整条滑下来时不会「半透明糊着走」；
- **音乐按钮是歌单读出来之后才出现的**，用 `@starting-style` 给它一个入场起点，
  所以它是淡入 + 轻微上浮，而不是「啪」地冒出来（不支持的浏览器直接出现，功能不受影响）；
- **`app-ready` 看门狗**：入场由 `<html class="app-ready">` 触发，那个类是 `index.html` 自己的脚本加的；
  `common.js` 里兜了一个定时器，万一那段脚本没跑到（报错 / 被扩展干扰），
  1.2 秒后会自己补上 —— 否则导航栏会永远停在 `opacity:0`、整个看不见；
- 开了「减少动态效果」时：导航栏相关元素**直接显示、不做动画**。

### 关于「加载页」（已取消）

网站早期有一个带进度条的**加载页**（遮罩 + 光斑 + logo + 百分比），现在**已彻底删除**：

- **删掉的**：加载页 DOM、它的 CSS 与 6 个关键帧、整段进度模拟脚本（资源里程碑 + 2.2 秒兜底），
  以及 `--preloader-*` 那组变量 —— `index.html` 因此从 652 行降到 500 多行；
- **保留的只有「宣布就绪」**：`html.app-ready` 是导航栏与首屏入场动画的触发条件，
  现在由一个十几行的小脚本负责（等两帧再宣布，先让「未就绪」的初始状态画一次，入场动画才会真的跑起来）；
- **雨滴 / 视差不受影响**：它们本来就是「听 `app:ready` 事件」而不是「查类」；
- **还有一层保险**：`common.js` 里有看门狗 —— 1.2 秒后若还没有 `app-ready` 就自己补上，
  万一页面脚本没跑到（报错、被扩展干扰），导航栏也不会永远停在透明状态。
### 深浅色切换的过场动画（整页粒子飞散）

点按钮切换深浅色时，**整个画面会按网格碎成许多小方块，从切换按钮的位置向外飞散消失**，
新主题在下面露出来。

- **实现**（都在 `common.js` 里；`styles.css` 只有一条 `.theme-scatter` 规则）：
  盖一张 `position:fixed` 的 canvas 铺满视口，每格一个粒子 ——
  1. 先按网格**逐格取样页面上真实的背景色**（`elementFromPoint` + 按元素缓存
     `getComputedStyle`，几百格也只有几十次计算），所以第一帧看起来就是**这张页面被像素化了**，
     而不是一堆乱色块；
  2. 每个粒子记下「从按钮向外」的速度，以及**按距离递增的出场延迟** ——
     于是形成一圈从按钮扩散出去的波，而不是全场一起消失；
  3. 立刻把主题切过去，并临时加 `.theme-vt` 关掉全站元素自身的颜色过渡，
     让露出来的直接就是新主题；粒子一边向外飞一边缩小淡出；
  4. 动画结束移除 canvas、去掉 `.theme-vt`。
- **性能**：格子大小按屏幕面积自动算（大约 700 格上下，手机更少），只画实心方块、
  不做旋转和阴影，所以每帧都很便宜；屏幕越大格子越大，粒子总数不会失控；
- **降级**：没有 canvas 2d、或开了「减少动态效果」→ 直接切换，不创建任何元素；
- **连点多次**：新的一次会先把上一张画布撤掉，不会叠两层。

**iOS 上「网址栏那一小块」**（浏览器 UI 不归网页管，画布盖不到它）：

- 靠两样东西跟主题：CSS 的 `color-scheme`（浅色块 `light` / 深色块 `dark`）+ `<meta name="theme-color">`。
  `color-scheme` 尤其关键 —— 它决定 iOS 网址栏与「首屏还没上色时」的底色，只设 `theme-color` 不够；
- 页头内联脚本里**一进来就**把两者按已保存/系统主题设好（不用等 CSS 加载），所以不会出现一块颜色不对；
- **加载层显示期间**，`theme-color` 用加载层自己的底色（浅 `#f6f7fb` / 深 `#080814`），
  加载结束后切回主题底色，这样那一小块和页面是对上的；
- **切换过场期间**，`theme-color` 会在旧色→新色之间**分步插值**（约每 70ms 一步，动画结束时精确落到目标色），
  所以它不再是「一步闪过去」，而是跟着粒子飞散一起变。

> 想调效果，改 `common.js` 里这几个数就行：
> `var dur = 620`（飞散时长，毫秒）、`sampleColors` 里的 `(w * h) / 700`（格子数量，改大 = 更细碎）、
> 以及粒子对象里的 `vx / vy`（飞出去的速度和方向）。



**升级这个组件**：下载新版覆盖 `theme-button.js` 后，上面 7 处改动要重做一遍；
别忘了给 `sw.js` 的 `CACHE_VERSION` +1，否则老访客拿到的还是缓存里的旧文件。

## 背景音乐

导航栏右边那个**音乐按钮**（音符图标 + 「音乐」）点开是一个**浮窗播放器**：
显示正在播放的歌名，有 **上一首 / 播放暂停 / 下一首**，下面是**歌单列表**（点歌名直接切歌）。
点浮窗外面或按 `Esc` 关闭。手机屏幕会缩成「音乐」，更窄的屏幕只剩图标。

**只有访客点了播放才会响**：浏览器不允许网页自己出声，必须有一次用户手势。各种自动播放的做法都试过了
（进站试播、第一次点击就播、进站就下载音乐），结果不是白下载几 MB、就是把首屏拖慢，
而访客终究还是要点一下。所以现在只保留最简单也最可靠的做法：**点了才播，不点就不下载**。

> **为什么不能对所有访客都做到「进站即播」？**
> 这是浏览器的自动播放策略，网站绕不过去。有声音的媒体必须满足下面之一才允许自动播放：
> 访客在页面上有过一次手势；或访客自己把浏览器 / 系统设成了允许自动播放；
> 或他以前在这个站上播过媒体、被 Chrome 记进了「媒体参与度」白名单。
> 所以「别的网站能自动播放」，通常是因为**你**在那个站播过、或者**你的**设置允许。
> 唯一能保证所有访客都「进站即播」的办法，是加一个「点击进入」的遮罩 ——
> 那一下点击就是浏览器要的手势，代价是访客必须先点一下才能看到内容。

### 如何新增音乐（手把手）

**第 1 步 · 把文件放进 `audio` 文件夹**

把音乐文件复制进 `audio/`。文件名请用**全小写英文 + 连字符**，例如 `my-song.mp3`。

> **千万别用中文、日文或空格做文件名**（像 `打上花火.mp3`、`One Last Kiss.mp3`）：
> 它们在网址里会被编码成 `%E6%89%93%E4%B8%8A…` 这种，容易出现看不见的坑。
> 现有的 8 首已经全部改成小写英文名了（见上面那张表）。

**第 2 步 · 在 `audio/playlist.json` 里加一行**

用记事本打开 `audio/playlist.json`，在方括号里加一条（注意**每条末尾的逗号**）：

```json
[
  { "src": "audio/one-last-kiss.mp3", "title": "One Last Kiss", "artist": "宇多田ヒカル", "default": true },
  { "src": "audio/my-song.mp3", "title": "新歌的歌名", "artist": "歌手名" }
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `src` | ✅ | 文件路径，必须和第 1 步的文件名**一模一样** |
| `title` | — | 列表里显示的歌名；不写就显示文件名 |
| `artist` | — | 歌手；不写就不显示 |
| `default` | — | 写 `true` = 默认曲（**整个列表只写一条**）。访客点播放先从它开始，列表里也会先高亮它 |

**第 3 步 · 顺序**

**数组的顺序就是列表里的顺序** —— 想调顺序，把这几个 `{...}` 上下移动即可。现在是：
日文歌在上（打上花火、好きだから。、失恋ソング…、One Last Kiss），英文歌在下。

**第 4 步 · 上传**

把改动提交推送，约 1 分钟生效；或者把音乐文件丢给我，我替你改名、写 json、上传。

**注意事项**

- 单首不能超过 **25 MiB**（Cloudflare 单文件上限）；
- **访客一进网站就会把整个歌单下载完**，歌越多、总量越大（现在 8 首 ≈ 65 MB）。
  想把总量压下来，就把 MP3 转成 **128 kbps**（当背景音乐听不出差别），总量约能降到 1/3；
- 转码后**文件名保持不变**（直接覆盖原文件）就不用改 json。

---

**底下是规则细节**（不看也能用）：

歌单来源有优先级，**都不用改代码**：

**① 想让列表显示真实歌名 → 建 `audio/playlist.json`**（推荐，还能写歌手）：

```json
[
  { "src": "audio/bgm-1.mp3", "title": "歌名一", "artist": "歌手" },
  { "src": "audio/bgm-2.mp3", "title": "歌名二" }
]
```

- `src` 必填；`title` 不写就显示文件名；`artist` 可以省略；
- 想让某一首**成为默认曲**，在那一条上加 `"default": true`（只加一条）。访客点播放就从它开始，
  列表里也会先高亮它 —— 浏览器不允许自动出声，所以「默认播放」只能是「默认选中、点一下就从它开始」；
- 这个文件不存在或读不出来，就自动走 ②。

> **⚠️ 一旦建了 `playlist.json`，就由它完全决定歌单** —— 文件名不再有任何约定，
> 编号探测（②）也不会再生效。想加歌就在 json 里加一行，`src` 写对路径即可；
> 文件叫 `bgm.mp3`、`song2.mp3`、`magnolia.mp3` 都行。

**② 只按编号命名放进 `audio/` 文件夹**（**只在没有 `playlist.json` 时**才走这条，列表里显示「第 N 首」）：

| 文件名 | 作用 |
|---|---|
| `audio/bgm-1.mp3` | 第 1 首 |
| `audio/bgm-2.mp3` | 第 2 首 |
| `audio/bgm-3.mp3` | 第 3 首（最多 30 首） |

- 页面加载时从 1 开始**依次探测** `bgm-1.mp3`、`bgm-2.mp3`……**遇到不存在的就停**，
  所以**编号必须连续** —— 有 1、2、4 却没有 3 的话，只会放到第 2 首。

**③ 都没有 → 退回单曲 `audio/bgm.mp3`**（就是现在的情况）；连它也没有 → 按钮不显示。

**播放规则**：顺序随机，一首放完随机换下一首（不会连着放同一首）；**上一首**按真实播放历史
回退，到头顶了就重播当前这首；只有一首时，效果就是循环播放。

文件名请用小写英文，避免网址编码问题。

> **为什么歌名不能自动读出来？**
> 从文件名读只能得到 `bgm-1` 这种名字；要读 MP3 里内嵌的 ID3 歌名，得先只取文件开头一小段
> 再去解析它。音频现在支持 Range 了（见「音频的缓存与分段下载」一节），技术上做得到 ——
> 但 ID3 有 v1 / v2 好几个版本，文字编码也是五花八门（UTF-8 / UTF-16 / Latin-1），
> 解析代码又多又容易出错。为省掉 `playlist.json` 里一行歌名而引入这些复杂度并不划算，
> 所以歌名仍然由你自己写 —— 好处是还能自定义成任何你想要的样子。

### 重复进站不会重新下载

歌曲下载后会留在浏览器缓存里。**再次进站不会再下载一遍**：

1. 页面先问浏览器缓存「这首有吗」—— **有就直接算「已下载」**（一个字节都不走网络，也不用把整首再读一遍）；
2. **缓存里没有的才真正下载**，下载完同样写进缓存，下次也不用再下；
3. 播放时若缓存那份需要校验，最坏情况是发一个很小的请求拿到 `304`（没有内容），**不会重下整首**。

所以老访客第二次进站，几乎是瞬间所有歌都变成 ✓。只有当访客**清空浏览器数据 / 换设备 / 换浏览器**，
才需要重新下载 —— 也就是你要的「有的就不下，没有的才下」。

### 音频的缓存与「分段下载」（Range）

这一节讲两件让音乐更顺的事，它们分别由 `_headers` 和 `src/worker.js` 实现。

**① `_headers`：让浏览器不用每次回来「问一遍」**

Cloudflare 给静态资源的默认响应头是 `Cache-Control: public, max-age=0, must-revalidate`，
意思是「可以用缓存，但每次使用前都必须回来确认一次」。音频文件内容永远不变，所以
`_headers` 里给 `/audio/*.mp3`（以及 m4a / ogg）改成了 `max-age=31556952, immutable`：
浏览器可以直接用本地那份，**省掉一次往返校验**。

> ⚠️ **以后换歌不要沿用同名文件！** 老访客的浏览器会一年内一直用缓存里那一首。
> 正确做法：**换文件名**，或者在 `audio/playlist.json` 里给它加 `?v=2` 之类的后缀。

> 注意：`_headers` 的多条规则是**叠加**的，不是后者覆盖前者。
> 所以**不能**写成 `/audio/*` —— 那样 `playlist.json` 也会被套上一年缓存，歌单就更新不了了。
> 歌单必须保持 `max-age=0, must-revalidate`。

**② `src/worker.js`：让音频支持「只取需要的那一段」**

Cloudflare 的静态资源服务**不支持 Range**（实测：带 `Range` 头也返回 `200` + 整个文件，
没有 `Content-Range`）。后果是拖进度条要等整个文件下载到那个位置；部分浏览器（尤其 Safari）
对媒体分段要求更严。

所以加了 `src/worker.js`，配合 `wrangler.jsonc` 里的 `assets.run_worker_first`，
**只让音频文件**（`.mp3 / .m4a / .ogg`）先经过 Worker：

| 请求 | 响应 |
|---|---|
| 不带 `Range` | `200` + 整个文件（**流式转发，不占内存**） |
| `Range: bytes=a-b` | `206` + 只回这一段 + `Content-Range` |
| `Range: bytes=-N` | `206` + 最后 N 个字节 |
| 起点越界 | `416` + `Content-Range: bytes */总长` |
| 多段 Range | 按规范允许的做法忽略，回整个文件 |

页面、样式、脚本、图片**完全不经过 Worker**，仍是静态资源直接服务（也不占 Worker 的每日请求额度）。
歌单 `playlist.json` 同样不经过它，所以缓存策略不受影响。

> 想改这段逻辑前，请先读 `src/worker.js` 顶部的注释 —— 那里记着 4 个**实测踩出来的平台事实**
> （资源库无视 Range、资源库不给 `Content-Length`、`_headers` 对 Worker 响应无效、
> `env.ASSETS.fetch` 不能只传路径），改错任何一条都会让音频挂掉。

### 下载失败 / 超时 / 没下 —— 都会自动重来

| 情况 | 会不会自动重下 |
|---|---|
| 下载**失败**（网络错误 / 服务器报错） | ✅ 立刻重试，间隔 1s → 2s → 4s（共 3 次） |
| 下载**超时**（单首超过 30 秒没下完） | ✅ 算作失败，走同一套重试 |
| **还没轮到下载**的歌 | ✅ 后台队列会依次把它下完 |
| 一首歌连续失败到用完 3 次 | ✅ 整个歌单跑完后**再自动来一轮**（最多 2 轮，每轮隔 15 秒）；**每次打开浮窗**也会再自动试一次 |
| 试完还是不行 | ⚠️ 这一首标成 `!`，点一下就能重下；其它歌照常 |
| 慢网（2G/3G）或开了「节省流量」 | ❌ 不预下载（省流量优先）；那时点哪首都能边下边播 |

### 为什么切歌会有小延迟，怎么优化的

浏览器开始播一首新歌之前，**必须先把那个音源加载并校验一遍**。音频现在已经设成
`immutable` 长缓存（见上一节），所以**命中缓存时不会再回源校验**；但如果访问者换设备、
清了缓存、或正好是第一次听这首，那这一步仍然省不掉。所以「换 src 再 play()」
在冷启动时必然有一段可见延迟。

优化做法：页面里放了**两个 `<audio>`** —— 一个正在播，另一个专门**提前把下一首加载好**
（`preload="auto"`）。切歌时直接播那个已经准备好的元素，几乎瞬间开始。

- 任何时刻只有一个元素在响（切换前会先暂停另一个）；
- 随机模式下「下一首」是**提前定好**的，保证预先加载的那首就是接下来要播的那首；
- 第一次点「播放」也一样：默认曲下载完就提前装进备用元素，不用等。

### 换页会怎样：同一首歌 + 同一进度会跟着走

站点是多页面结构，**换页时浏览器会销毁整个页面（包括播放器），所以声音必然中断一下**
（大约 1~2 秒）。这是浏览器机制，不是 bug —— 要真正「不断音」，只能把整站改成**单页应用**。

能做到的是**状态同步**（首页 ↔ 文章页，双向）：

| 内容 | 是否跟着走 |
|---|---|
| 正在播 / 选中的那一首 | ✅ 记住（存在 `sessionStorage`，**每个标签页独立**，不会互相干扰） |
| 播放进度（第几秒） | ✅ 记住：播放中每 2 秒记一次，暂停、切到别的标签页、离开页面时也会记 |
| **暂停 / 播放状态** | ✅ 走之前是**暂停**的 → 新页面就停在那一秒、不会自己响；走之前**正在播** → 新页面会尝试自动接着播。⚠️ **iOS 上必然要点一下**（系统不认恢复后的播放授权）：界面会写「点一下继续播放」+ 主按钮呼吸提示，**点页面任何地方都行** |
| **音量** | ✅ 记在 `localStorage`，**同一浏览器的所有页面 / 标签页共用** |
| **顺序 / 随机** | ✅ 同上 |
| 「上一首」的播放历史 | ❌ 不跟（每个页面各自记） |
| 新开一个标签页 | ❌ 从默认曲开始（状态是**每个标签页独立**的） |
| **按浏览器「后退 / 前进」** | ✅ 会重新对齐（浏览器可能不重载页面而是从「前进后退缓存」原样解冻，代码里用 `pageshow` 处理了这种情况） |

换页之后有两种结果：

1. **浏览器允许自动出声** → 直接接着播（同一首、同一秒）；
2. **浏览器不允许**（更常见：新页面还没有任何用户操作）→ 页面会**等你第一次点击 / 按键**，
   然后接着播同一首、同一秒。（点「会跳走的链接」那一下不算，避免刚续上又换页。）

### 进度条（拖动跳转）

面板里的顺序是：**正在播放 → 播放控件 → 进度条 → 音量 → 歌单**。
进度条左边是当前时间、右边是这首歌的总时长。

| 行为 | 说明 |
|---|---|
| 外观 | 轨道是**圆角胶囊**（6px，手机 8px），已播部分是主题蓝，未播部分是浅灰 |
| 可点区域 | **26px 高（手机 32px）** —— 手指点得准，不要求你精确戳那条细线 |
| 拖动时 | **只更新左边的预览时间**，松手才真正跳转 —— 边拖边跳会不停中断缓冲，反而更卡 |
| 还没读到时长 | 滑块**置灰拖不动**（刚点开一首、或这首歌还在下载），读到时长后自动可用 |
| 拖到最末尾 | 会停在结尾前 0.25 秒，避免立刻触发「播完 → 切下一首」 |
| 暂停时拖动 | 立刻把新位置写进跨页状态，换页后从那里接着播 |
| 播放时拖动 | 位置会在下一次自动记录（约 2 秒内）或离开页面时落盘 |
| 键盘 | 滑块可以用方向键操作（无障碍支持），左右箭头微调 |

**拖动为什么需要 Range**：跳到歌曲中间时，浏览器要么「直接只要那一段」（服务器支持 Range 才行），
要么「从头顺序下载到那里」。这就是 `src/worker.js` 存在的理由（见上一节）。
没有它的话，拖到一首歌的 4 分钟处就得等整首慢慢下过去。

> ⚠️ **踩过的坑四：滑块后面出现「白块」。**
> `<input type="range">` 自己带一条**浏览器默认轨道**。当时我们把渐变画在 input 元素本身上，
> 却没给 `::-webkit-slider-runnable-track` / `::-moz-range-track` 写样式 ——
> 于是浏览器把它的默认浅色轨道**垫在我们的渐变下面**，看起来就是「后面有一块白」。
> 正确写法（现在用的）：
> 1. input 元素本身 `background: transparent`；
> 2. 轨道画在 **轨道伪元素**上（`border-radius: 999px` 做成胶囊）；
> 3. Chrome/Safari 的圆点要用**负 `margin-top`** 手动居中（`(轨道高 − 圆点高) / 2`），
>    **Firefox 不能加**（它会自动居中，加了反而偏）。
> 音量条用的是同一套写法，已调部分靠 `--bgm-vol-fill` 上色。

### 手机上（尤其 iOS）的两个限制

这两件事**不是 bug，是 iOS 的系统策略**，代码里做了力所能及的补救：

**① 音量不能用网页控制 → 换成一句提示**

iPhone / iPad 上**所有浏览器都是 WebKit**，而 WebKit 在 iOS 上会**忽略 `audio.volume`**：
你设了它不报错，读回来还是你刚设的值 —— 但声音大小完全由设备侧键决定。
所以「设完读回来」这种判断在 iOS 上会**误判成支持**（以前就是这个原因：音量条在那儿、划了却没反应）。
现在的做法是 **UA 判断 + 回读**双重检查，判定不支持时**把滑块换成「音量请用设备按键调节」的提示**，
而不是摆一个划不动的控件。电脑和安卓不受影响，滑块照常可用（而且做得更紧凑了）。

**② 回退 / 前进后不能自动出声 → 必须点一下**

桌面浏览器从「前进后退缓存」恢复页面时，之前那次点击带来的播放授权还在，所以能直接接着播。
**iOS 恢复页面后不认这个授权**，`play()` 会被拒绝 —— 这一下点击没法省。

能做的补救（都已实现）：

| 补救 | 效果 |
|---|---|
| 界面明确写着「点一下继续播放」 | 不会让人以为播放器坏了 |
| 主播放按钮**呼吸灯**提示 | 一眼看到该点哪里（开了「减少动态效果」时改成静态蓝圈） |
| 点**页面任何地方**都行（不只按钮） | 除了「会跳走的链接」——那一下马上就要换页 |
| 同时监听 `pointerdown` / `touchend` / `click` / `keydown` | 有些 WebKit 版本只给 touch 事件，不能漏；监听器是**单例**，不会越挂越多 |
| 点到「还没下载完的歌」也直接边下边播 | 以前这种情况点了**完全没反应**，最容易被当成坏了 |
| 被拒时**保留「在播」意图与位置** | 换页后还会再尝试续播，不会静默降级成「暂停」 |
| **位置立刻设、不只等元数据** | iOS 上 `loadedmetadata` 可能迟迟不来。以前只挂这一个监听 = 永远不跳（听着就是「从头播」）。现在 `seekTo()` 立刻试一次，再在元数据/时长/可播/开播时各补一次 |
| **区分两种失败** | `AbortError` 只是「这一次被打断」（换源、竞态）→ 自动重试最多 3 次；只有 `NotAllowedError` 才需要访客点一下。以前一律弹提示，桌面端也会「有概率要再点一次」 |
| **纠正只在开播前做** | 位置纠正一旦允许「播放中途也生效」，缓冲恢复时的 `playing`/`canplay` 会把已经听到的进度**拽回旧位置**（听起来就是「播着播着重新放」）。现在只允许在 `currentTime < 3 秒`（也就是播放还没真正推进起来）时纠正，开播那一刻纠一次就收工 |
| **离开页面时绝不写一个更小的位置** | 这是最隐蔽的一个：iOS 上自动续播那次尝试会把音源装进元素，但**位置设不上去**（没元数据时设 `currentTime` 不生效），元素停在 0 秒。`pagehide` 写状态时若信了 `el.currentTime`，就把 0 写了进去 —— 下一个页面读到 0，点一下自然从头播。现在：**还没真正出声时，绝不写比「记着的续播意图」更小的位置** |
| **续播意图有独立备份** | `resumeTime` 会在好几条路径被清零。现在另存一份 `pendingResume`（src + 秒数），除非「真的按这个位置播起来了」或访客明确换歌/拖动，否则不许丢 |

**桌面端为什么也可能「有概率要再点一次」**：`play()` 被拒有两种原因，我们以前不分。
另外旧代码挂了一个**完全不需要的 `beforeunload`** —— 它是「前进后退缓存」（bfcache）的历史杀手
（web.dev 原话：以前会让页面失去 bfcache 资格，现在也不可靠，除非绝对必要否则别用）。
没有它，Chrome/Edge 更愿意把页面放进缓存；**缓存恢复时播放授权还在，回退就能直接接着播**。

> 这里还修过几个会丢进度的真 bug（都是真机报出来后才定位到的）：
> 1. 切歌时写状态读的是 `currentTime`，而那一刻新音源刚设上、读出来必然是 0 ——
>    会把上次记着的位置**冲成 0**，还会顺手把「离开时在播」写成「没在播」。
> 2. 读状态时用 `active()` 找元素，而**真正装着这首歌的可能是备用元素**（两个 `<audio>` 交替用）。
>    一旦两者不一致，位置判断全错，暂停分支还会重复赋 `src` 把位置重置 ——
>    现在统一走 `elForCurrent()`。
> 3. iOS 没有手势时不肯加载音源 → 元素报 `error` → 旧代码 `playNext()` →
>    `requestPlay()` 里 `resumeWantPlay`/`resumeTime` 双双清零 → **续播位置彻底丢失**。
>    现在：正等续播时的 `error` 不当成播放失败，保住意图和位置，只强下一次干净音源。

### 浮窗底部的 Spotify 按钮

浮窗最下面那个绿色按钮，点开会在**新标签页**打开 Spotify 歌单。

### 兼容性（哪些能、哪些不能）

| 项目 | 情况 |
|---|---|
| 音频格式 | ✅ MP3 —— 所有浏览器、所有系统都支持 |
| 音乐按钮 + 浮窗播放器 | ✅ 全平台（`<audio>` + 普通 DOM） |
| 进站后自动下载整个歌单 | ✅ 全平台；**慢网（2G/3G）与「节省流量」模式自动跳过** |
| 每首歌的下载状态小图标 | ✅ 全平台（✓ 已下载可播放 / 转圈 下载中 / ! 下载失败） |
| 重复进站 | ✅ 已下载的**不会重新下载**（只查缓存）；缓存里没有的才下 |
| 点了还没下载完的歌 | ✅ 全平台：**排队等它下完自动播放**（只认最后一次点击，绝不会同时播两首、也不会跑去播更早点过的那首） |
| 点了「播放」但当前曲没下完 | ✅ 一样排队等下载完自动播，并先弹个小提示 |
| iOS 上排队后的自动播 | ⚠️ 系统可能拒绝「不是直接点击触发」的播放，那时会提示「已经下载好了，点一下播放」 |
| 下载超时 / 失败自动重试 | ✅ 全平台（30 秒超时；退避 1s → 2s → 4s，最多 3 次） |
| 上一首 / 下一首 | ✅ 全平台（优先跳到**已下载好**的歌；都没下好就先排队） |
| **顺序播放 / 随机播放** | ✅ 全平台（右上角按钮切换，选择记在浏览器里） |
| **音量调节** | ✅ 电脑 / 安卓有（紧凑滑块 + 百分比）；**iOS 上滑块会换成一句「音量请用设备按键调节」的提示** —— iOS 忽略网页音量，摆个划不动的滑块只会让人以为坏了 |
| 自动播放 | ❌ 浏览器策略不允许（见上面说明），本项目已放弃 |
| **拖动进度条** | ✅ 全平台（拖动跳转靠 `src/worker.js` 提供的 Range 分段下载；还没读到时长时滑块置灰；轨道 6px / 手机 8px，**可点区域 26px / 32px 高**，手指点得准） |
| 切换页面 | ⚠️ 同一标签页内**歌与进度会同步**（同一首 + 同一秒），但**声音会中断约 1~2 秒**（多页面站点的必然） |

### 其它说明

- **一首歌都没有时按钮不会显示**（页面加载时会读 `audio/playlist.json`，或发几个很小的 HEAD 请求探测编号），
  不会出现「点了没反应」的按钮；这些请求都**不下载音频本身**；
- **一进网站就会把整个歌单下载好**：等页面加载完成后再开始、逐首依次下载，不影响打开速度，
  访客点播放就能立刻响。**代价很大，务必知道**：现在 8 首共 **65 MiB** —— 也就是
  **每个访客首次进站都要下载 65 MB**（同一访客不会重复下载，之后只是校验一下有没有变）；
- 慢网与省流量会**自动跳过**预热：`navigator.connection` 报 `slow-2g` / `2g` / `3g`，
  或者访客开了「节省流量」，就完全不下载；
- 想彻底关掉：把 `common.js` 里 `startWarm();` 那一行删掉；
- **想大幅降低这个数字**：把 MP3 从 320 kbps 转成 128 kbps（当背景音乐听不出差别），
  总量能从 65 MB 降到约 26 MB；
- 默认音量 0.4 —— 在 `common.js` 里搜 `bgm.volume` 可以改；
- **音频不会被 Service Worker 缓存**（`sw.js` 里按扩展名排除了），否则听几首歌就会占满访客浏览器的缓存。

## 部署

### Cloudflare Workers（当前实际使用的方式）

站点跑在 **Cloudflare Workers + 静态资源** 上，不是 Pages。仓库已经和 GitHub 连好，
**只要把改动推到 `main` 分支就会自动重新部署**，不需要做别的：

```
推送到 main  →  Cloudflare 自动执行 npx wrangler deploy  →  约 1 分钟生效
```

`wrangler.jsonc` 就是这份部署配置，每一项都别随手改：

| 字段 | 当前值 | 说明 |
|---|---|---|
| `name` | `raindream-personal-website` | Worker 的名字。**写错会变成新建一个项目，而不是更新现有的** |
| `compatibility_date` | `2026-10-06` | 运行时兼容日期，改了可能影响行为 |
| `main` | `src/worker.js` | 我们自己的 Worker 脚本（只负责音频的「分段下载」，见背景音乐那节） |
| `assets.directory` | `./` | 整个仓库目录都会作为网站内容 |
| `assets.binding` | `ASSETS` | Worker 里要用 `env.ASSETS.fetch()` 取文件，绑定必须起个名字 |
| `assets.run_worker_first` | `["/audio/*.mp3", "/audio/*.m4a", "/audio/*.ogg"]` | **只有这些文件**先经过 Worker；其余仍是静态资源直接服务。**不能写成 `/audio/*`**，否则歌单也会被接管 |
| `assets.not_found_handling` | `404-page` | 找不到文件时返回最近的 `404.html`，状态码 404 |

> ⚠️ **踩过的坑一：404 页面不生效。** `not_found_handling` 的默认值是 `none`，
> 也就是「什么都不返回」——访客看到的是一片空白。它既不在 HTML 里、也不在 JS 里，
> 只在 `wrangler.jsonc` 里。少了这一项，根目录的 `404.html` 根本不会被使用。

> ⚠️ **踩过的坑二：仓库里的东西会被整个发布。** 因为 `assets.directory` 是 `./`，
> 仓库里的每个文件都会变成网站内容（实测 `.git/config` 曾经可以被公开访问）。
> 不想被上传的（`.git`、`work/`、`src/` 等）必须写进 `.assetsignore`，格式和 `.gitignore` 一样。
> `src/` 被排除后，`/src/worker.js` 访问会返回 404（源码不会泄露），但 Worker 本身照常运行。

> ⚠️ **踩过的坑三：本地 `wrangler dev` 会无限重载。** 因为 `assets.directory` 是 `./`，
> wrangler 自己的 `.wrangler/` 状态目录也在里面，它写一次状态就触发一次重载，
> 日志会不停刷 `Local server updated and ready`。
> **想在真实平台上验证又不想碰线上，推荐用：**
> `npx wrangler versions upload`（上传一个预览版本，会给你一个 `*.workers.dev` 预览地址，
> 线上一根汗毛都不会动）。验证满意了再推 `main` 让它正式部署。

### 本地预览 404 页面

`python -m http.server` **不会**自动使用 `404.html`，它返回的是 Python 自带的错误页。
想在本地看 404 页面的样子，直接双击打开 `404.html` 就行。

> **关于站内链接为什么是相对的**（`blog.html` / `index.html`）：
> 线上 `/blog.html` 和 `/index.html` 会各自 **307 跳转**到 `/blog` 和 `/`，所以点一次链接
> 会多一次同源跳转（同一个连接、几十毫秒，几乎感觉不到）。
> 保留相对路径是为了**双击 HTML 文件就能在本地点着看**。
> 哪天想省掉这一跳，把它们改成 `/` 和 `/blog` 就行 —— 代价是本地双击预览时链接会失效。
> （`404.html` 是个例外：它会在任意路径下被返回，所以里面的链接**必须**用根绝对路径。）

## 离线说明

主页完全不依赖外部网络。博客页用的 Markdown 渲染库 `marked.umd.js` 现在也是仓库内的本地文件
（锁定版本 18.1.0），所以断网时博客页也能正常渲染，不再依赖 cdn.jsdelivr.net。

404 页面会向 `loliapi.com` 要一张随机背景图：失败或超时会自动重试两次，仍然不行就静默退回渐变底色，
访客不会察觉出过错，也不影响阅读和按钮点击。开启了「节省流量」模式的访客不会请求这张图。

Service Worker 缓存策略（`sw.js`）：

- **页面、样式、脚本、歌单**（`index.html`、`blog.html`、`styles.css`、`common.js`、`marked.umd.js`、
  `posts.js`、`audio/playlist.json`）全部走**网络优先** —— 刷新就是最新版，不需要手动清缓存；
- **为什么这些必须一致**：它们曾经走缓存优先，出过两次真实的坑 ——
  一次是「新 HTML + 旧 CSS」让导航栏按钮文字被挤成一列，一次是**旧歌单被缓存住，
  老访客只看到一首歌**。所以现在只有图片和字体走缓存优先；
- **图片 / 字体**（`avatar.webp` 等）走**缓存优先** —— 速度快、省流量；若替换了这类文件，
  必须把 `sw.js` 顶部的 `CACHE_VERSION` 加 1（当前是 `v15`），老访客才会拉到新版本；
- 预缓存是**逐个文件**进行的：某一个文件取不到，不会连累其它文件，也不会让整次安装失败；
- 离线访问一个从没访问过的地址时，返回的是 404 页面（状态码也是 404），而不是把首页当成「成功」返回。
